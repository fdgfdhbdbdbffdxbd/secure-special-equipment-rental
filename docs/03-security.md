# Механизмы защиты

## Вход и полномочия

Регистрация хеширует пароль через Argon2id со случайной солью библиотеки. Сессия использует случайный SID и абсолютный TTL два часа. Выход удаляет серверную запись. Функции require и rental_access проверяют роль и принадлежность объекта. Для чужой заявки клиент получает 404.

## Шифрование

DATA_KEY — Base64-представление случайного ключа длиной 32 байта. Для каждого значения генерируется nonce 12 байт. Формат поля — nonce и результат AESGCM.encrypt с 16-байтным тегом. Контекст AAD связывает файл с заявкой и договором. При InvalidTag возвращается 503 и фиксируется contract_invalid. Прототип использует key_version=1. При смене ключа существующие значения требуют миграции.

## Защита форм и ответов

Flask-WTF CSRFProtect проверяет POST-формы. Cookie по умолчанию имеют Secure, HttpOnly и SameSite=Lax. DEV_HTTP=1 предназначен для локального HTTP-запуска. Шаблон Jinja экранирует комментарии. Ответы включают CSP, nosniff и no-store.

Файл принимается от сотрудника после подтверждения заявки, проверяются лимит 5 МиБ и префикс PDF. Выдача оформлена как attachment. PDF-анализатор и антивирусная обработка в прототипе отсутствуют.

## Согласованность и аудит

SELECT FOR UPDATE блокирует заявку при изменении статуса и прикреплении договора. Уникальность rental_id предотвращает два документа для одной заявки. Действие и запись аудита сохраняются транзакционно. Журнал содержит идентификаторы и коды событий.

## Эксплуатационные границы

Для рабочего размещения требуются HTTPS, ограничение попыток входа, резервирование ключей и БД, процедура ротации и анализ PDF. Учебный стенд проверяет перечисленные в протоколе сценарии. Секреты и базы локального стенда исключены из Git через .gitignore.
